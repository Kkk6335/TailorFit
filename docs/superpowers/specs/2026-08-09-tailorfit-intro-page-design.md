# TailorFit 项目介绍页设计

## 1. 背景与目标

TailorFit 是一个面向成年用户的微信小程序，帮助用户根据个人目标、训练条件与身体信息建立四周训练计划，并在本机完成训练打卡和历史回顾。本页面的目标是吸引新用户扫码体验，而不是替代小程序本体。

页面必须同时适配桌面端与移动端：桌面端适合浏览介绍并扫描二维码，移动端适合直接阅读和继续分享。内容只使用当前项目已实现的能力，不虚构训练效果或医疗能力。

## 2. 视觉方向

采用暖象牙纸色（`#f4f0e8`）背景、近黑石板色（`#2b2b28`）正文与深色区块、陶土橙（`#bd5b3e`）强调的基础设计语言。导航控件层（顶部导航栏、导航胶囊链接、CTA 按钮）采用 Apple Liquid Glass 液态玻璃材质：高透光环境 tint、Fresnel 边缘光、双层克制阴影、WebGL 折射位移与按压液态形变，并随背景明暗自动切换文字对比；内容卡片与正文保持干净底色，不玻璃化。展示型深色区块保留深石板色底和衬线大标题，形成象牙色与深色交替的编辑节奏。

字体层级：

- UI 与正文使用系统无衬线字体，保证中文跨平台可读性。
- 英文产品名与大标题允许使用 Georgia 等系统衬线回退字体，延续编辑式排版节奏。
- 辅助标签使用等宽字体与较大字距。

色彩必须满足 WCAG 2.2 AA 对比度要求；陶土橙只用于 CTA、编号、二维码说明等少量重点。

## 3. 页面信息架构

### 3.1 顶部导航

显示 TailorFit 品牌、功能、流程、安全说明与一个“扫码体验”行动入口。桌面端固定在页面顶部并支持锚点跳转；移动端保留品牌与 CTA，导航链接折叠或隐藏，不引入复杂菜单。

### 3.2 首屏

左侧为品牌标签、主标题“把训练计划，变成真正适合你的日常。”、简短说明和主要 CTA；右侧为体验版二维码、有效期提示与一张小型产品事实卡。

事实卡使用真实信息：4 周计划、6 个内置计划、本地优先、每日打卡。二维码引用 `C:/Users/Rz/Downloads/TailorFit体验版（8月16日前有效）.png`，页面需用相对资源副本，避免依赖用户下载目录。

### 3.3 产品定义区

用一段简洁叙述说明 TailorFit 将“目标、训练经验、器械、可训练时间、身体信息”组织成可执行的四周训练计划，并明确 AI 只是辅助生成，不做医疗诊断或效果承诺。

### 3.4 功能展示区

使用 8 个内容块呈现：

1. AI 个性化四周计划：可选择关闭思考模式，生成过程带有额度提示。
2. 计划库：包含新手增肌、进阶增肌、减脂全身、居家自重、核心与体能、拉伸与活动度六个内置计划。
3. 本地创建：手动选择目标、环境、难度、训练重点和动作，不发送资料、不消耗 Token。
4. 训练仪表盘：用一周日期条、今日训练/恢复状态、本周训练天数、完成组数、平均 RPE 和进度条，快速知道自己现在在哪里。
5. 真实打卡：记录计划剂量、实际组数、次数、重量、RPE、睡眠、心情与备注。
6. 本地训练分析：切换本周、4 周、12 周范围，查看训练天数、分钟、组数、平均 RPE、完成率、训练量、体重和动作表现。
7. 当前计划可调整：可以只修改正在执行计划的组数和次数，不会改动计划库里的原计划，让安排随着真实状态变得更贴合。
8. 数据可带走：训练档案、计划与记录支持 JSON 导入导出；导出不包含 API Key，导入不会覆盖当前设备的 API Key。

### 3.5 使用流程区

以 4 个编号步骤呈现“了解自己 → 选择方式 → 完成训练 → 回看进步”。每个步骤只写一个用户能理解的动作，避免变成技术说明。

### 3.6 安全与隐私区

采用深色反差区块，说明：API Key、档案、计划与历史默认只保存在当前微信客户端；AI 生成计划时，用户选择的健康与训练信息会直接发送给 DeepSeek，而不会经过 TailorFit 后端；风险状态用户不会获得 AI 计划并应先咨询专业人士；TailorFit 不提供诊断、治疗、营养处方或训练效果承诺。

### 3.7 适用人群与结尾 CTA

用简短标签列出新手、想重建习惯的人、居家训练者和有目标但缺少计划的人。结尾再次展示二维码、有效期和“扫码体验 TailorFit”按钮。二维码旁应有文字说明，不能只依赖图片传达行动。

## 4. 交互与响应式行为

- 所有导航、CTA 和二维码说明使用原生锚点或可访问按钮，不依赖 JavaScript 才能阅读。
- 页面支持键盘 Tab 导航，`:focus-visible` 必须有清晰的 2px 外轮廓。
- 二维码图片提供明确的替代文本。
- 桌面端内容最大宽度约 1180px，首屏为左右两栏；移动端在 768px 以下改为单栏，二维码卡片位于主文案之后。
- 功能卡片桌面端使用 3 列或不等宽编辑网格，移动端改为单列并保留清晰的编号和标题。
- 动画使用轻微的入场位移与导航控件的液态按压形变，必须尊重 `prefers-reduced-motion: reduce`。
- 二维码图片使用 `object-fit: contain`，不裁切；在小屏至少保持 180px 可扫描宽度。

## 5. 实现边界

- 使用当前工作区的独立静态页面，不修改 TailorFit 小程序业务代码。
- 页面可在无构建工具的情况下直接打开；优先使用单个 `index.html` 与本地资源目录。
- 不接入真实 API、不收集表单、不保存用户数据。
- 不加入未确认的下载链接、登录流程或小程序深链；当前主要行动入口是二维码。

## 6. 验收标准

- 桌面端首屏能在不滚动的情况下看到项目定位、二维码和有效期。
- 移动端 375px 宽度下无横向溢出，二维码仍可识别。
- 页面完整介绍当前已实现的功能，并明确 AI、隐私和健康安全边界。
- 视觉上符合暖象牙、近黑、陶土橙基础色系统；导航控件具备 Liquid Glass 液态玻璃材质（高透光、边缘折射光感、双层阴影、按压形变、明暗自适应），内容卡片不玻璃化。
- 所有图片有替代文本，链接/按钮有明确名称，焦点状态可见。
- 静态结构检查通过，HTML/CSS/JS 无明显语法错误，页面可直接从本地打开。
